How TrainingDxBench works

Training failures are often hardest when nothing crashes. The script finishes, metrics are emitted, and artifacts are saved, yet the realized training behavior or model outcome is still wrong.

Have you debugged a run that looked fine, but was not?

The failure may take hours, days, or weeks to understand.

A coding agent writes a training script. It runs without errors, but the training behavior or model performance is not what you expected. There is no exception to follow. Instead, you have learning curves, logs, checkpoints, evaluation outputs, and a growing suspicion that something in the pipeline is wrong.

Eventually, the cause turns out to be a subtle data problem, incorrect normalization, improperly applied mask, target mismatch, stale state, artifact bug, or misleading evaluation. TrainingDxBench asks whether an Agent can recover that causal chain.

Why diagnosis matters

Writing training code is only the beginning.

Agents that improve models must understand training dynamics, recognize when a completed run has gone off track, diagnose the mechanism, and repair it before the failure compounds.

We place Agents in realistic tasks based on authentic model development failures. Each Agent receives the completed flawed workspace and its evidence, then investigates and edits it under a fixed wall clock budget.

What is a training defect?

A realistic error that completes normally but changes what happened.

A valid study demonstrates a controlled, reproducible difference between matched flawed and corrected workflows. The mechanism must be recoverable from the evidence and difficult enough to require genuine investigation rather than an obvious contradiction or trivial puzzle.

Δp

Training process difference

Data exposure, supervision, loss, gradients, updates, state, artifacts, inference, scoring, or selection.

Δq

Training outcome difference

Model behavior, task performance, deployment capability, or the officially reported conclusion.

Example task: padding free chat packing

A training run with normal loss curves silently mixes independent conversations across packed boundaries.

padding-free-chat-packing model failed
SFT padding free packing attention masks label alignment Qwen2.5-0.5B
Flawed
  1. attention_mask = torch.ones_like(input_ids)

    The dense mask disables packed-segment detection, so later documents can attend to unrelated earlier documents.

  2. labels = input_ids.clone()

    Reset positions remain supervised, so each previous document predicts the next document's first token.

→
Corrected
  1. - "attention_mask": torch.ones_like(input_ids),

    Omitting the dense mask lets reset position IDs define independent packed segments.

  2. labels[position_ids == 0] = -100

    Ignoring reset-position labels removes cross-document boundary targets.

              What does the diagnosis Agent see?
              

                Only an anonymous independent copy of the completed flawed
                workspace. The Agent cannot access Task.md, the
                corrected workspace, Oracle, scorer, repository parent, or run metadata.
              

            

            

              What happens when the 1,800 second budget expires?
              

                Workspace and shell access stop. The same Agent invocation returns
                its best final assessment, and the result records
                budget_exhausted: true. Exhaustion alone does not decide
                whether the repair resolves the task.
              

            

            

              Does collection evaluation rerun the Agent repair?
              

                No. Archived paired scoring establishes task validity. A single
                tool free Judge then compares the Agent diagnosis and submitted
                repair with the canonical reference.
              

            

            

              Can I author on different hardware?
              

                Yes. Author hardware may differ, but the task must remain
                reproducible within the official two RTX A6000 ceiling while
                preserving effective batch, update budget, and mechanism semantics.
